Reporte de bugs - /sign-in
Fecha: 2026-07-07
URL probada: http://127.0.0.1:4321/sign-in
Entorno: playwright-cli contra la app local Astro SSR

1) El login por correo queda bloqueado aunque las credenciales tengan formato valido
Severidad: Alta
Pasos para reproducir:
- Abrir `/sign-in`
- Escribir un correo con formato valido, por ejemplo `test@example.com`
- Escribir una contraseña cualquiera, por ejemplo `wrongpassword`
- Esperar unos segundos sin interactuar con otros elementos
Resultado esperado:
- El boton `Iniciar sesión` deberia habilitarse para permitir enviar el formulario
Resultado actual:
- El boton sigue deshabilitado
- El campo oculto `cf-turnstile-response` permanece en `null`
- No se renderiza ningun `iframe` ni widget visible de Turnstile para que el usuario complete o valide el reto
Impacto:
- El acceso por correo puede quedar inutilizable porque el usuario no tiene forma visible de desbloquear el submit

2) La pagina genera errores de consola de Google/FedCM apenas carga
Severidad: Media
Pasos para reproducir:
- Abrir `/sign-in`
- Revisar la consola sin interactuar con la pagina
Resultado esperado:
- La pagina no deberia lanzar errores en consola durante la carga normal
Resultado actual:
- Aparecen errores como `Provider's accounts list is empty.` y `[GSI_LOGGER]: FedCM get() rejects with NetworkError: Error retrieving a token.`
Impacto:
- Genera ruido tecnico, dificulta debugging y sugiere que el flujo de Google One Tap no se maneja de forma resiliente

3) El flujo de Google OAuth dispara errores por `window.closed` bloqueado por COOP
Severidad: Media
Pasos para reproducir:
- Abrir `/sign-in`
- Hacer clic en `Google`
- Revisar la consola de la pagina principal
Resultado esperado:
- El popup OAuth deberia abrirse sin provocar errores en la pagina principal
Resultado actual:
- Se registran errores `Cross-Origin-Opener-Policy policy would block the window.closed call.` en `src/modules/auth/islands/FormSignIn.tsx:211`
Impacto:
- El flujo OAuth produce errores evitables y puede volverse fragil segun navegador o politica de seguridad

4) El control `Recuérdame` expone un checkbox duplicado y sin etiqueta clara
Severidad: Media
Pasos para reproducir:
- Abrir `/sign-in`
- Inspeccionar el bloque `Recuérdame`
Resultado esperado:
- Deberia existir un solo control de checkbox correctamente etiquetado
Resultado actual:
- La UI expone un checkbox visible con etiqueta y ademas otro checkbox de `1x1px` sin nombre claro en el arbol accesible
Impacto:
- Puede confundir a lectores de pantalla y deteriora la accesibilidad del formulario

5) El boton `Cambiar tema` tiene un area tactil demasiado pequena
Severidad: Baja
Pasos para reproducir:
- Abrir `/sign-in` en desktop o mobile
- Inspeccionar el boton `Cambiar tema`
Resultado esperado:
- Un control interactivo superior deberia acercarse a `44x44px` para touch/accesibilidad
Resultado actual:
- El boton mide aproximadamente `20x20px`
Impacto:
- Reduce usabilidad en pantallas tactiles y dificulta la interaccion precisa

Notas:
- La validacion nativa del correo invalido si funciono correctamente.
- El popup de Google si llega a abrirse, pero el flujo deja errores de consola en la pagina principal.
